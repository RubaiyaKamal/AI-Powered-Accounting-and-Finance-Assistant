## Prompt

Phase 2 — Specification & Workflow Design (SDD)
This project must follow Spec-Driven Development (SDD): write clear specifications first, then
implement against those specs. Your specs should define features, API contracts, data models,
and AI-agent behavior before implementation.
• Create a complete workflow diagram of the system on Lucidchart or draw.io (this tool
choice is a requirement, not optional) — covering user flows, AI agent flow (how a user
request travels from UI → API → agent → tools → database → response), and data flow.
The diagram's shareable URL must be submitted with your deliverables.
• Write feature specs (what each feature does, inputs, outputs, edge cases) before coding it.
• Keep your specs in the repository (e.g., a /specs folder) so we can see that development
followed the specs.

## Response snapshot

No `.specify/` scaffolding existed in the repo yet, so `/sp.constitution` could not
operate on an existing template as instructed. Identified the toolkit in use as
Spec-Kit-Plus (`panaversity/spec-kit-plus`, already installed globally as the `sp`/
`specifyplus` CLI) via the pre-existing `sp.*` command files in `~/.claude/commands/`.
Ran `sp init --here --ai claude --script sh --force` to bootstrap `.specify/memory/`,
`.specify/templates/`, `.specify/scripts/bash/`, project-local `.claude/commands/sp.*.md`,
and `CLAUDE.md` (the init hung when stdin wasn't redirected from `/dev/null` — a
non-interactive-environment quirk, resolved by piping `< /dev/null`).

Read `.specify/templates/plan-template.md`, `spec-template.md`, `tasks-template.md`, and
`CLAUDE.md` to confirm none hardcode principle names (all reference the constitution
generically), so no propagation edits were needed there. Drafted and wrote
`.specify/memory/constitution.md` v1.0.0 with six principles derived from this project's
research and the Phase 2 requirement above: (I) Spec-Driven Development (NON-NEGOTIABLE),
(II) Deterministic Financial Computation (LLM orchestrates/narrates, never invents
numbers — ties to `research/task-automation-mapping.md`), (III) Human-in-the-Loop for
Regulated/High-Risk Actions (audit flags, fraud detection, tax summaries), (IV)
Branch-Per-Feature & PR-Only Merges (ties to the existing `github-commit-workflow` skill),
(V) Documented Architecture & Workflow (mandates the Lucidchart/draw.io diagram this
prompt requires, with its shareable URL recorded once produced — flagged as an open
TODO since the diagram doesn't exist yet), and (VI) Simplicity & Traceability (YAGNI +
PHR/ADR traceability). Added Technology & Architecture Constraints and Development
Workflow & Quality Gates sections, and a Governance section covering amendment
procedure and versioning. Prepended a Sync Impact Report noting the initial ratification,
which templates were checked (all compatible as-is), and the pending workflow-diagram
and README TODOs.
